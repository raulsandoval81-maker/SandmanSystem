# P-000019 correction startup repair

## Production evidence and cause

On November 1, 2026 the production service in `sandmandashboard/us-central1`
served revision `correctp000019historicalallocation-00002-z8t` (100% traffic).
Its source package uses `main: index.cjs`, whose only statement exports
`lib/billing/correctP000019HistoricalAllocation.js` directly. The repository's
normal package uses `main: lib/index.js`; that entry point initializes Admin.
The isolated package bypasses it, as generated by
`.github/workflows/release-pr427-elias-production-function.yml`.

At 20:11:18.849 PST the production POST returned HTTP 500 in 100 ms;
trace `1ccb557d32770c5f250a53658db720bc`. Callable request verification passed,
then `requireProposalStaffAccess` called `getFirestore()` and threw
`FirebaseAppError: app/no-app`. No receipt validator or transaction was reached.
This is an execution exception, separate from the browser-control timeouts.

The repair initializes the default app, if absent, inside this callable before
staff authorization. It neither imports the broad entry point nor changes any
other function, authorization check, receipt policy or transaction.

## Verification

Use Node.js 22. The startup regression loads the compiled correction directly,
as the production wrapper does, in fresh child processes. It uses the real Admin
SDK app registry and Firestore initialization, with in-memory denied staff reads
instead of network requests. Cold and named-app-only cases fail with `app/no-app`
before the repair. Tests also cover reuse of the default app, repeat invocations,
and unauthenticated rejection. No production credentials or emulator are needed.

## Single-function deployment, only after explicit approval

Start in a clean isolated checkout at the full reviewed repair commit SHA, using
the approved production deployment identity and Node.js 22. Verify the checkout
SHA and review the diff before these commands. The old PR427 workflow pins an
older source SHA: rerunning it would omit this repair.

Run the verification commands above first, then package only the existing
callable. Do not copy `.env` files or invoke the normal broad entry point.

```sh
task_release_dir=$(mktemp -d)
export task_release_dir
mkdir -p "$task_release_dir/functions"
cp -R functions/lib "$task_release_dir/functions/lib"
cp functions/package-lock.json "$task_release_dir/functions/package-lock.json"
node <<'NODE'
const fs = require('node:fs');
const path = require('node:path');
const root = process.env.task_release_dir;
const pkg = JSON.parse(fs.readFileSync('functions/package.json', 'utf8'));
pkg.main = 'index.cjs';
pkg.scripts = {};
fs.writeFileSync(path.join(root, 'functions/package.json'), JSON.stringify(pkg, null, 2));
fs.writeFileSync(path.join(root, 'functions/index.cjs'),
  'module.exports = { correctP000019HistoricalAllocation: require("./lib/billing/correctP000019HistoricalAllocation.js").correctP000019HistoricalAllocation };\n');
fs.writeFileSync(path.join(root, 'firebase.json'),
  JSON.stringify({ functions: { source: 'functions', runtime: 'nodejs22' } }, null, 2));
NODE
npm ci --omit=dev --prefix "$task_release_dir/functions"
node <<'NODE'
const path = require('node:path');
const { createRequire } = require('node:module');
const root = path.join(process.env.task_release_dir, 'functions');
const packagedRequire = createRequire(path.join(root, 'index.cjs'));
const entry = packagedRequire('./index.cjs');
const keys = Object.keys(entry);
if (keys.length !== 1 || keys[0] !== 'correctP000019HistoricalAllocation' ||
    !entry[keys[0]].__endpoint?.callableTrigger) throw Error('Unexpected callable exports');
const { getApps } = packagedRequire('firebase-admin/app');
if (getApps().length) throw Error('Discovery must not initialize unrelated entry points');
console.log('Single-callable discovery passed; no handler invoked.');
NODE
```
