# Purpose

This document defines authority, responsibility, and operational relationships within Sandman System.

Every permission, workflow, routing decision, and software role should respect this hierarchy.

Hierarchy is organizational.

Permissions are implementation.

Do not confuse the two.

# SYSTEM ADMIN

Purpose

Platform governance.

Responsibilities

• Platform ownership

• Global configuration

• Security

• Organization management

• Access authority

• Platform policies

• Exceptional intervention

Admin governs.

Admin does not operate daily coaching.

# ATHLETE

Purpose

---

# Authority Principle

Authority flows downward.

Responsibility flows upward.

Each level serves the level below it.

Leadership exists to create success for others.

---

# Software Principle

Every software permission should reflect organizational hierarchy.

Never grant software authority that violates organizational authority.

---

# Growth Principle

This hierarchy should remain valid whether Sandman operates:

one location

ten locations

one hundred locations

The implementation may evolve.

The hierarchy should remain stable.

# Final Principle

Great organizations create clarity.
